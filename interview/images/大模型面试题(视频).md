## 一、Agent 操作数据库，防止删表/越权的方案

### 一、账号权限隔离（最核心）

1）**最小权限原则**：给 Agent 单独建数据库账号，只授予业务必需的权限。

- 只读场景：只给 `SELECT`，不给 `INSERT/UPDATE/DELETE`。
- 写入场景：按表、按字段授权，禁止 `DROP/ALTER/TRUNCATE/GRANT` 等 DDL 和高危权限。
- 不给 `SUPER/RELOAD/FILE/SET` 等管理员权限，不使用 root/高权限账号。

2）**读写分离账号**：查询走只读账号，写入走受限写入账号，两者不混用。

3）**行级/列级权限**：用数据库的行级安全（RLS）、列级授权限制 Agent 只能访问授权范围内的数据，防止越权看敏感字段。

### 二、SQL 层拦截与校验

1）**SQL 白名单/语法解析**：Agent 生成 SQL 后，先用解析器（如 SQLGlot、JSQLParser）解析 AST，校验语句类型，拦截 `DROP TABLE`、`TRUNCATE`、`ALTER`、`DELETE` 无 `WHERE`、`UPDATE` 无 `WHERE`、全表扫描等高危语句，直接拒绝执行。

2）**强制条件校验**：写操作必须带主键/业务过滤条件，禁止无 WHERE 的全表更新删除；校验目标表、目标列是否在授权清单内。

3）**SQL 审查后再执行**：高危 DDL、大批量写入必须经过人工审批或二次确认，Agent 无权直接落库。

### 三、架构与流程控制

1）**中间层网关**：Agent 不直连数据库，统一走数据库代理/中间层（如内部 DB Gateway、ORM 网关），由网关做鉴权、SQL 校验、限流和审计。

2）**工具白名单**：在 Agent 的 Function Call/MCP 工具里，只暴露查询工具和受限写入工具，不提供通用的"执行任意 SQL"工具；每个工具内部固定表和操作类型。

3）**事务与回滚**：写操作先开事务，执行前做影响行数预估，超过阈值（如删改超 N 行）自动回滚并告警；关键变更先备份。

### 四、审计与监控

1）**全量审计日志**：记录谁（哪个 Agent/用户）、什么时间、执行了哪条 SQL、影响行数、返回数据范围，便于追溯。

2）**异常监控告警**：对 DDL、大批量删改、越权表访问、跨业务库查询实时告警，熔断可疑 Agent。

3）**脱敏与限流**：敏感字段返回前脱敏，限制单次查询行数和调用频率，防止批量拖库。

### 五、数据兜底

1）**备份与快照**：关键库定期备份、开启快照/回滚能力，误操作可恢复。2）**环境隔离**：测试、生产库严格隔离，Agent 默认只能访问测试库，生产库需额外授权。

### 一句话总结

**账号最小权限 + SQL 解析拦截高危语句 + 网关统一鉴权 + 工具白名单 + 审计监控兜底**，从权限、校验、流程、审计四层防止删表和越权。
